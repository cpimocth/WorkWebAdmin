# CPI Price Entry + Supabase

เว็บบันทึกราคารายเดือนสำหรับ CPI โดยยึด workflow จากหน้าเดิมและ logic รายงานเดิม:

- เลือก ปี / เดือน / ชุด G-L-U-N / จังหวัด / อำเภอ-เขต / กลุ่ม / แหล่งจัดเก็บ
- เดือนใหม่ใช้ปุ่ม **เตรียมข้อมูลเดือนนี้** เพื่อสร้างรายการจาก Master
- `ราคาปัจจุบัน` ของเดือนก่อนจะถูกนำมาเป็น `ราคาเดือนก่อน` และ `ราคาเปรียบเทียบ` ของเดือนใหม่โดยอัตโนมัติ
- REL = `ราคาปัจจุบัน / ราคาเปรียบเทียบ * 100`
- REL เก็บที่ 5 ตำแหน่ง และการแสดง 2 ตำแหน่งใช้ค่าที่ปัด 5 แล้วมาปัด HALF UP ต่อ
- คำนวณ GeoMean ตาม CODE7 เฉพาะรายการ Checked
- รายงาน GeoMean ภาพรวม, GeoMean รายภาค (ถ้า Master มีคอลัมน์ภาค), จำนวนขึ้น/ลง/เท่าเดิม
- Export Excel
- Import Master จาก Excel/CSV โดยตรวจรหัสสินค้า 16 หลักและรหัสแหล่ง 10 หลัก

## 1) สร้าง Supabase

1. สร้าง Supabase Project
2. เปิด SQL Editor
3. Run ไฟล์ `supabase_schema.sql`
4. ไปที่ Authentication > Users แล้วสร้างผู้ใช้งาน (email/password)
5. คัดลอก **Project URL** และ **Publishable key** (หรือ legacy anon key)

> ห้ามใช้ Secret key / service_role key ใน browser

## 2) เปิดเว็บ

วิธีง่ายสุดสำหรับทดสอบในโฟลเดอร์นี้:

```bash
python -m http.server 8080
```

แล้วเปิด `http://localhost:8080`

กด **ตั้งค่า Supabase** แล้วใส่ Project URL + Publishable/anon key จากนั้น Login

## 3) นำเข้า Master

กด **Import Master** แล้วเลือก Excel/CSV

ระบบพยายามตรวจคอลัมน์อัตโนมัติ โดยต้องมีอย่างน้อย:

- รหัสสินค้า / COMMODITY_CODE: 16 หลัก
- รหัสแหล่ง / รหัสร้านค้า / SHOP_CODE / DILLER_CODE: 10 หลัก

รองรับคอลัมน์เพิ่มเติม เช่น:

- ลักษณะจำเพาะ / DESCRIPTION
- หน่วย
- แหล่งจัดเก็บ
- จังหวัด
- อำเภอ/เขต
- ภาค
- ชุด/กลุ่ม
- G / L / U / N (ค่า Checked, 1, true ฯลฯ)
- ชื่อรายการ
- ผู้ดูแล

Duplicate key ของ Master คือ `รหัสสินค้า 16 หลัก + รหัสแหล่ง 10 หลัก` และ Import จะ upsert ทับข้อมูล Master เดิมของคู่รหัสเดียวกัน

## 4) เริ่มบันทึกเดือน

1. เลือกปีและเดือน
2. กด **เตรียมข้อมูลเดือนนี้**
3. ระบบสร้าง monthly rows สำหรับ Master ที่ Active และจะไม่ทับแถวที่มีอยู่แล้ว
4. ถ้ามีข้อมูลเดือนก่อน ระบบดึง current price เดือนก่อนเป็น previous/compare ของเดือนใหม่
5. กรอกราคาปัจจุบัน ระบบคำนวณ REL ทันที
6. กด **บันทึกทั้งหมด**
7. ติ๊ก Checked สำหรับรายการที่ต้องนำไปคำนวณ และติ๊กยืนยันเมื่อพร้อมส่ง

## 5) Security

SQL เปิด RLS และอนุญาตเฉพาะ role `authenticated` ให้อ่าน/เพิ่ม/แก้ไขข้อมูลร่วมกัน ไม่มีสิทธิ์สำหรับ `anon` และหน้าเว็บไม่ใช้ service_role key

หากภายหลังต้องจำกัดตามจังหวัด/ผู้ดูแล สามารถเปลี่ยน RLS policy ให้ผูกกับ `auth.uid()` และตารางสิทธิ์ของเจ้าหน้าที่ได้โดยไม่ต้องเปลี่ยนสูตรคำนวณในหน้าเว็บ
